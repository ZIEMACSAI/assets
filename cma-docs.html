Guides and reference for the Cluster Management Agent for PowerHA

Overview

The Cluster Management Agent for PowerHA is a team of specialist AI agents, hosted by ZIEMACS and reached through IBM watsonx Orchestrate, that monitors, diagnoses, and, when enabled, helps recover IBM PowerHA SystemMirror clusters. It is advisory by default: it reads cluster state on demand and provides diagnosis, impact analysis, and recommendations. It installs nothing on your nodes. Access to your cluster is always authenticated and least-privilege: in advisory mode the agent uses read-scoped credentials to read cluster state, and when a connection is opted into remediation, it uses credentials scoped to the approved actions. The agent never holds more access than the mode in use requires.

How it works

The agent is reached as an external agent through watsonx Orchestrate. A supervisor routes your questions to the right specialist among seven domain agents covering cluster operations, monitoring, diagnostics, change reporting, deployment, disaster recovery, and anomaly detection. The agents read PowerHA, CAA, and replication state on demand to answer questions and assess cluster health. All capability is governed by a single enforcement policy, so what the agent can and cannot do on your environment is explicit and auditable.

Advisory mode and remediation mode

By default the agent is advisory only: it reads and recommends, it does not change your cluster. Remediation is a separate capability that is off by default and enabled per connection, at your choice. When you opt a connection into remediation, the agent can perform a curated set of recovery actions, and each action runs only after an operator approves that specific action. Nothing is changed automatically and nothing is changed without a person approving it.

Remediation actions

When a connection is opted into remediation, the agent can perform three recovery actions, each only after operator approval:

Move a resource group to a healthy node: brings its storage, service address, and application back online together.
Restart the cluster
Rejoin a node

These three are validated end to end against live PowerHA behind the approval gate. Additional actions are added over time as they are validated.

Detection and monitoring

At launch the agent detects on demand: it reads cluster state when you ask. PowerHA continues to raise its own alerts; the agent provides intelligence on top of that state and, when opted in, operator-approved remediation. Continuous proactive monitoring is on the roadmap following launch.

Security and data handling

The agent is agentless with respect to your cluster: no ZIEMACS software runs on your servers or nodes. Access is always authenticated and follows least privilege. In advisory mode the agent uses read-scoped credentials; when a connection is opted into remediation, credentials are scoped to perform the approved actions, key-based, and used only after an operator approves a specific action. Credentials are referenced by path and never stored in configuration or logs. All data is encrypted in transit. See our Privacy Policy for details.

Getting started

After subscribing through the IBM Cloud catalog, you receive instructions to register the agent in your watsonx Orchestrate environment and connect it to your cluster. You can begin in advisory mode with read-scoped credentials, and opt a connection into operator-approved remediation later when you choose.

Detailed setup and operations documentation will be available at launch.
