Frequently asked questions

How does the agent connect to my cluster?

The Cluster Management Agent is advisory by default and runs as a hosted agent reached through IBM watsonx Orchestrate. It reads cluster state on demand and provides diagnosis and recommendations without any agent software installed on your nodes, using read-scoped, customer-provided credentials. Remediation is off by default; a customer can enable operator-approved remediation per connection, and only then does the agent use credentials scoped to the approved actions to perform a recovery action, over SSH, after a person approves it.

Which IBM PowerHA versions are supported?

The Cluster Management Agent supports PowerHA SystemMirror 7.2 and later on AIX 7.2 and later.

Is my data secure?

Yes. The agent is agentless with respect to your cluster: no ZIEMACS software runs on your servers or nodes. Access is always authenticated and follows least privilege. In advisory mode the agent uses read-scoped credentials to read cluster state; when a connection is opted into remediation, credentials are scoped to the approved actions, key-based, and used only after an operator approves a specific action. Credentials are referenced by path and never stored in configuration or logs, and all data is encrypted in transit. See our Privacy Policy for details.

What remediation actions can the agent perform?

When a connection is opted into remediation, the agent can perform a curated set of recovery actions, each only after an operator approves that specific action: moving a resource group to a healthy node (which brings its storage, service address, and application back online together), restarting the cluster, and rejoining a node.

Can I change my plan?

Yes, you can change plans through the IBM Cloud console. Contact support for assistance.
